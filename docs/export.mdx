`open-pages export` builds each page into a self-contained static folder. It runs the same Vite pipeline as the dev preview (same React transform, same Tailwind, same aliases), so what you export is what you saw.

## The export CLI

```bash
# Every page in the workspace → export/<id>/
npx open-pages export

# Specific pages by id
npx open-pages export launch status-board

# Custom output directory (default: export/)
npx open-pages export launch --out-dir dist/pages
```

Page ids are the folder names under `pages/`, the same ids the preview uses. Passing an unknown id fails with the list of available pages. Each build prints with its kind and build time:

```text
ok  export/launch/  react · 1240ms
ok  export/plain-html/  html · 310ms
2 pages → export/
```

Flags:

| Flag | Meaning | Default |
|------|---------|---------|
| `[pages...]` | Page ids to export | all pages |
| `--out-dir <dir>` | Output directory, relative to the project root | `export` |

## What you get

```
export/launch/
  index.html
  assets/
    index-B3k9xQ.js
    index-Dm2a1F.css
    hero-Hx81sP.png
```

- **`index.html`** with the page's `meta.title` as `<title>` and `meta.description` as the description meta tag, mounting the React component.
- **Hashed JS and CSS** with only the Tailwind utilities the page actually uses.
- **Relative URLs.** Every reference is `./assets/...`, so the folder works from a domain root, a subpath, or `file://`.
- **No inspector instrumentation.** The `data-op-loc` attributes that power click-to-source exist only in dev.

HTML pages build straight from their folder: `index.html` plus whatever CSS and JS it references, bundled and hashed the same way.

## Deploying

The output is plain static files. Some common targets:

<AccordionGroup>
  <Accordion title="Netlify">
    Drag the folder onto the Netlify dashboard, or point a site at it: `netlify deploy --dir export/launch --prod`.
  </Accordion>
  <Accordion title="Vercel">
    `vercel deploy export/launch --prod`, or set the project's output directory to `export/<id>` and its build command to `npx open-pages export <id>`.
  </Accordion>
  <Accordion title="Cloudflare Pages">
    `npx wrangler pages deploy export/launch`, or connect the repo with build command `npx open-pages export launch` and output directory `export/launch`.
  </Accordion>
  <Accordion title="GitHub Pages">
    Commit the folder to a `gh-pages` branch or upload it as a Pages artifact in an Actions workflow. Relative URLs mean the `/<repo>/` subpath just works.
  </Accordion>
  <Accordion title="S3 / any static host">
    `aws s3 sync export/launch s3://my-bucket --delete`. Serve `index.html` as the default document.
  </Accordion>
</AccordionGroup>

## The workspace build

`open-pages build` is different: it builds the **whole workspace viewer** (the home page, folders, theme gallery, and every page behind its viewer chrome) into `dist/`, for publishing the browsing experience itself. Use `export` when you want the page; use `build` when you want the workspace. See [CLI reference](/reference/cli#build) and the `build` options in [Configuration](/reference/config#build).
