open-pages ships two packages with two binaries:

- **`@autono/create-open-pages`** provides `init`. Run it with `npm create @autono/open-pages@latest` from anywhere, no install needed.
- **`@autono/open-pages`** provides `open-pages` with everything else (`dev`, `build`, `preview`, `export`, `sync:skills`, `update`). It is a dependency of every workspace, so inside a workspace `npx open-pages <command>` resolves to it. The scaffolded `package.json` also maps npm scripts: `npm run dev`, `npm run build`, `npm run preview`, `npm run export`, `npm run sync:skills`, `npm run update`.

When passing flags through an npm script, separate them with `--`:

```bash
npm run export -- launch --out-dir out
```

Both binaries accept `-v, --version` and `-h, --help`.

## init

Create a new open-pages workspace.

```bash
npm create @autono/open-pages@latest [dir]
```

| Flag | Description |
| --- | --- |
| `[dir]` | Target directory. Prompted interactively when omitted in a terminal (defaults to `.`). |
| `-f, --force` | Scaffold into a non-empty target directory. Without it, a non-empty target errors (or asks for confirmation in a terminal). |
| `-n, --name <name>` | Override the package name. Defaults to the folder name. |
| `--use-npm` / `--use-pnpm` / `--use-yarn` / `--use-bun` | Pick the package manager for the dependency install. Only one may be passed. Without one, init detects your package manager and asks in a terminal. |
| `--no-install` | Skip dependency installation. |
| `--no-git` | Skip `git init` and the initial commit. |

What init does:

1. Copies the workspace template into the target directory: `pages/`, the shadcn set (`ui/`, `lib/`, `hooks/`, `styles/globals.css`, `components.json`), `assets/`, `themes/`, `open-pages.config.ts`, an `AGENTS.md` agent guide (linked as `CLAUDE.md`), and the six bundled agent skills under `.agents/skills/` (symlinked into `.claude/skills/`).
2. Sets the package name, marks the package private, and sets `@autono/open-pages` to a caret range on the version the CLI was built against (`^x.y.z`).
3. Writes a `.gitignore` covering `node_modules`, `dist`, `export`, and `.DS_Store`.
4. Installs dependencies (unless `--no-install`) and creates a git repository with a first commit (unless `--no-git`). Git setup is skipped automatically when the target sits inside an existing repository.

Directory names with characters that break shell commands (spaces, quotes) are rejected in non-interactive mode and corrected via a prompt in a terminal.

<Note>
On Windows, the `CLAUDE.md` link and skill symlinks are created as copies instead.
</Note>

## dev

Start the dev server. The workspace home lists every page; `/p/<id>` previews one live. See [Quickstart](/quickstart).

```bash
open-pages dev
```

| Flag | Description |
| --- | --- |
| `-p, --port <port>` | Port to listen on. Must be an integer between 0 and 65535. Defaults to `port` from [open-pages.config.ts](/reference/config), then 5173. |
| `--host [host]` | Expose the server on the network. Optionally pass a specific host. |
| `--open` | Open the browser on start. |
| `--no-skills-check` | Skip the built-in skills drift check. |

### Skills drift check

Before starting, `dev` compares the skills bundled in your installed `@autono/open-pages` against the copies in `.agents/skills/`, by content hash. If any skill was added or updated upstream:

- In a terminal, it asks `Sync now? (Y/n)` and runs the sync on confirmation.
- In non-interactive contexts (CI, agent shells), it prints a warning telling you to run `open-pages sync:skills` and continues.

Skip the check with `--no-skills-check` or by setting the environment variable:

```bash
OPEN_PAGES_SKIP_SKILLS_CHECK=1 open-pages dev
```

### Supervised process

The server runs in a supervised child process. An in-app update of `@autono/open-pages` can restart the server against the freshly installed package, and restarts reuse the same port.

## build

Build the workspace as a static site: the page browser, theme gallery, and viewer, with every page inside it, deployable to any static host. HTML pages are built into `__page/<id>/` inside the output.

```bash
open-pages build
```

| Flag | Description |
| --- | --- |
| `--out-dir <dir>` | Output directory. Defaults to `dist`. |

The `build` section of [open-pages.config.ts](/reference/config) controls which UI features the built site includes (page browser, viewer chrome). To publish a single page without the workspace around it, use [`export`](#export).

## preview

Serve the production build locally.

```bash
open-pages preview
```

| Flag | Description |
| --- | --- |
| `-p, --port <port>` | Port to listen on (integer, 0 to 65535). |
| `--host [host]` | Expose the server on the network. Optionally pass a specific host. |
| `--open` | Open the browser on start. |

## export

Build pages into self-contained static folders, without a running dev server. See [Export](/export).

```bash
open-pages export [pages...]
```

| Flag | Description |
| --- | --- |
| `[pages...]` | Page ids to export (the folder names under `pages/`). Omit to export every page. Unknown ids error and list the available ids. |
| `--out-dir <dir>` | Output directory. Defaults to `export`. |

Each page is written to `<out-dir>/<id>/` as `index.html` plus hashed assets with relative URLs, with a per-page line reporting the page kind and build time:

```
ok  export/launch/  react · 1240ms
```

React pages get a generated entry that mounts the component, with `meta.title` and `meta.description` written into the HTML head. HTML pages build straight from their folder.

```bash
# Export one page
open-pages export launch

# Export everything into out/
open-pages export --out-dir out
```

## sync:skills

Sync the bundled agent skills from your installed `@autono/open-pages` into the workspace.

```bash
open-pages sync:skills
```

| Flag | Description |
| --- | --- |
| `--dry-run` | Show what would change without writing. |

Drift detection is hash based: each skill directory (file paths plus contents) is hashed and compared against the workspace copy in `.agents/skills/`. Each skill reports one of three statuses:

- `added`: not yet present in the workspace
- `updated`: present but content differs from the installed package
- `unchanged`: identical

Changed skills are copied into `.agents/skills/` and symlinked into `.claude/skills/` (copied where symlinks are unavailable). To pull newer skills, run [`update`](#update), which upgrades the package and syncs in one step.

`open-pages dev` runs the same drift detection on startup, so most workspaces never need to call this by hand. See [For agents](/for-agents) for what the skills do.

## update

Update `@autono/open-pages` in this workspace to the latest version on npm, then sync the skills it ships.

```bash
open-pages update
```

| Flag | Description |
| --- | --- |
| `--force` | Reinstall even if the workspace is already on the latest version. |
| `--no-skills` | Skip the skills sync after installing. |

`update` checks npm's `latest` tag against the installed version and exits early if there is nothing to do. Otherwise it runs your package manager's install command (`npm install @autono/open-pages@latest`, or the `pnpm` / `yarn` / `bun` equivalent, detected from the lockfile) and then `open-pages sync:skills` from the freshly installed package. Your `pages/`, `open-pages.config.ts`, and everything else in the workspace are untouched.

The same update is available from the dev server: when a newer version exists, the home page shows an **Update** button. Restart `open-pages dev` after either path.
