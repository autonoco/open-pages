`open-pages.config.ts` sits at the workspace root and default-exports an `OpenPagesConfig`. The scaffolded file is empty, and every field is optional. A missing file means all defaults.

```ts open-pages.config.ts
import type { OpenPagesConfig } from '@autono/open-pages';

const openPagesConfig: OpenPagesConfig = {};

export default openPagesConfig;
```

The file is loaded with Vite's config loader, so it can be TypeScript and use imports. `dev`, `build`, `preview`, and `export` all read it. It is loaded once at startup, so restart the dev server after changing it.

<Note>
The agent guide scaffolded by `init` tells agents not to modify this file. Config changes are yours to make.
</Note>

## Fields

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `base` | `string` | `'/'` | Base public path (Vite's `base`). Set it when hosting a `build` output under a subpath. `export` output always uses relative URLs and ignores it. |
| `pagesDir` | `string` | `'pages'` | Directory scanned for pages. Each page is a folder with an `index.tsx` or `index.html` entry, see [Pages](/authoring/pages). |
| `themesDir` | `string` | `'themes'` | Directory holding theme bundles (`<id>.md`, `<id>.css` token overrides, `<id>.demo.tsx`), see [Themes](/authoring/themes). |
| `assetsDir` | `string` | `'assets'` | Shared assets directory, importable from pages via the `@assets` alias. |

The page stylesheet is not configured here: the runtime reads `tailwind.css` from `components.json` (default `styles/globals.css`) and uses that file for preview and export. The `@` alias always maps to the workspace root.
| `port` | `number` | `5173` | Dev server port. The `-p, --port` flag on [`open-pages dev`](/reference/cli) overrides it. |
| `allowedHosts` | `string[] \| true` | unset | Hostnames allowed to reach the dev server (Vite's `server.allowedHosts`). Needed when accessing the server through a proxy or tunnel hostname. `true` allows any host. |
| `locale` | `Locale` | unset | Deprecated. Seeds the initial UI language until the viewer picks one in the language switcher (their choice is then remembered locally). Locale objects (`en`, `ja`, `zhCN`, `zhTW`) come from `@autono/open-pages/locale`. |
| `build` | `OpenPagesBuildConfig` | all `true` | Feature flags for the static site produced by `open-pages build`. Ignored in dev, where everything is always enabled. |

## build

`build` controls which UI features ship in the built workspace site. Both default to `true`.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `showPageBrowser` | `boolean` | `true` | Include the page browser home, folders, and back-to-pages navigation. Turn off to publish a single page's viewer without a way to browse the rest. |
| `showPageUi` | `boolean` | `true` | Include the viewer chrome around the page: the header toolbar with viewport toggles. Turn off to show only the page itself. |

## Example

A workspace served under a subpath, on a fixed port, building a viewer-only site:

```ts open-pages.config.ts
import type { OpenPagesConfig } from '@autono/open-pages';

const openPagesConfig: OpenPagesConfig = {
  base: '/pages/',
  port: 4000,
  allowedHosts: ['pages.internal.example.com'],
  build: {
    showPageBrowser: false,
  },
};

export default openPagesConfig;
```
