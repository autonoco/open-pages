open-pages' agent integration is entirely file-based. There is no MCP server, no plugin, no SDK to wire up. A scaffolded workspace ships skills as markdown, instructions as `AGENTS.md`, and live state as a JSON file. Any agent that can read and write files works: Claude Code, Cursor, Codex, Gemini CLI, OpenCode, Windsurf, Zed, or anything else.

## The five skills

`npm create @autono/open-pages@latest` installs five skills into `.agents/skills/` and symlinks each into `.claude/skills/`, so Claude Code picks them up natively while other agents read them from the neutral `.agents/` location.

| Skill | Owns |
| --- | --- |
| `create-page` | The workflow for drafting a new page: scoping questions, theme selection, structure, hand-off. |
| `page-authoring` | The technical reference: file contract, Tailwind styling, layout and responsiveness, interactivity, assets and fonts, HTML pages, self-review. `create-page` and `apply-comments` defer to it for the how. |
| `apply-comments` | Processing `@page-comment` markers left by the [inspector](/inspector): find markers, apply the described edits, delete the markers. |
| `current-page` | Resolving deictic references. When the user says "this page" or "this element" without naming one, this skill reads the agent cursor to find what they mean. |
| `create-theme` | Authoring a theme bundle under `themes/`: a `<id>.md` spec (palette, typography, layout, fixed components) plus a runnable `<id>.demo.tsx`. |

## AGENTS.md and CLAUDE.md

The workspace root carries `AGENTS.md` and an identical `CLAUDE.md`. They are deliberately short: the hard rules (pages live at `pages/<kebab-id>/index.tsx`, do not touch `package.json` or `open-pages.config.ts`, no new dependencies) plus a routing table that points each kind of task at the right skill. Everything deeper lives in the skills, so the always-loaded context stays small.

## Keeping skills in sync

Skills are managed by `@autono/open-pages`. Do not edit them in place; local edits are overwritten on the next sync. To pull the latest versions:

```bash
npm run update
```

That upgrades the package and syncs in one step. `npm run dev` also detects drift on startup and offers to sync. To preview what a sync would change without writing anything:

```bash
npx open-pages sync:skills --dry-run
```

The drift check hashes each skill directory and reports every skill as `added`, `updated`, or `unchanged`. Sync copies changed skills into `.agents/skills/` and maintains the `.claude/skills/` symlinks, falling back to a plain copy on filesystems that refuse symlinks.

## The agent cursor: current.json

The dev server writes a live cursor on every navigation and inspector pick:

```
node_modules/.open-pages/current.json
```

```json
{
  "pageId": "meridian-launch",
  "pageTitle": "Meridian — Launch",
  "view": "pages",
  "pagePath": "pages/meridian-launch/index.tsx",
  "selection": {
    "line": 52,
    "column": 8,
    "tagName": "h1",
    "text": "Your analytics, turned into decisions"
  },
  "updatedAt": "2026-08-28T14:32:11.123Z"
}
```

- `pageId` and `pagePath` identify the page the human has open. `pagePath` is relative to the project root and points at `index.tsx` for React pages or `index.html` for HTML pages.
- `view` is `"pages"` while viewing a page, `"assets"` while browsing its asset manager.
- `selection` is `null` unless the human has picked an element in [inspect mode](/inspector). When set, `line` (1-indexed) and `column` (0-indexed) point at the JSX opening tag, `tagName` is the source tag, and `text` is the element's text content (up to 120 chars) as a sanity check.
- `updatedAt` is the last navigation or selection change. Use it to judge staleness: trust a fresh read, confirm before acting on one older than a few minutes.

This is what makes deictic instructions work. When the user says "make this bigger" or "tighten this page", the agent reads `current.json`, jumps to `pagePath` at `selection.line`, and edits, without asking "which page?". The cursor is live state, not conversation history: the `current-page` skill instructs agents to re-read it at the start of every deictic turn, because the human navigates between turns.

If the file is missing, the dev server has not been opened on a page yet. Agents are instructed to ask rather than guess.

## The @page-comment marker

Inspector comments persist as JSX comment markers inside the page source:

```
{/* @page-comment id="c-<8hex>" ts="<ISO>" text="<base64url(JSON)>" */}
```

- Inserted as the first child inside the element the comment refers to, spliced immediately after the opening tag's `>`.
- `text` decodes to JSON: `{"note": "...", "hint"?: "..."}`. The `note` is the human's verbatim comment.
- Being a JSX comment, it renders nothing and never affects the page.

The `apply-comments` skill carries the authoritative detection regex, the procedure for resolving each marker's target element, and the edge cases (self-closing elements, stacked markers, unresolvable notes). Agents apply edits in reverse line order so earlier edits do not invalidate later line numbers, then delete each marker they applied. A marker left behind means the edit was skipped, not forgotten.

## Dev server routes

The dev server exposes a small local API the workspace UI uses. Agents rarely need it, but it is there:

| Route | Purpose |
| --- | --- |
| `PATCH /__pages/:id` | Rename a page (writes `meta.title`). |
| `DELETE /__pages/:id` | Delete a page folder. |
| `POST /__pages/:id/duplicate` | Copy a page folder to a new id. |
| `GET /__comments?pageId=` · `POST /__comments/add` · `DELETE /__comments/:id` | List, add, and remove `@page-comment` markers. |
| `/__folders` | Home-page folders and assignments. |
| `/__assets` | Per-page and shared asset management. |
| `/__edit` | Source edits by line and column. |

Mutating routes only accept same-origin JSON requests.

## Working outside Claude Code

Nothing above depends on Claude Code. Cursor, Codex, and other agents get the same surface:

- `AGENTS.md` at the root is the standard entry point most agents already read.
- Skills in `.agents/skills/<name>/SKILL.md` are plain markdown. Point your agent at the relevant one, or reference it in your agent's rules file.
- `current.json` and `@page-comment` markers are plain files the dev server maintains regardless of which agent is attached.

For the human side of the loop, see [Inspect mode](/inspector). For what agents actually write, see [Pages](/authoring/pages).
