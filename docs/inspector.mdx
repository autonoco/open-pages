The viewer at `localhost:5173/p/<id>` runs the real page in a browser frame. Inspect mode adds a click-to-source layer on top: every element on the page maps back to the exact line and column in `pages/<id>/index.tsx` (or a component file under the page folder) that produced it. That mapping is what lets a human point at a rendered page and have an agent edit the right JSX.

Inspect mode works for React pages. HTML pages (`index.html`) are served verbatim and have no source map.

## Toggling inspect mode

Two ways:

- Click the **Inspect** button (crosshair icon) in the page toolbar.
- Press <kbd>i</kbd> anywhere in the viewer, including inside the page itself. Pressing it again toggles off. The shortcut is ignored while you are typing in an input or textarea.

The button enables once the page has mounted.

## Selecting an element

With inspect mode on, hovering outlines the innermost element under the cursor. Clicks are intercepted so links and buttons on the page do not fire. Click one and a selection panel appears with:

- **Tag**: the source JSX tag, like `h1` or `div`.
- **Source location**: line and column of the opening tag in the page source.
- **Text**: the element's text content, so you can confirm you picked the right node.

Press <kbd>Escape</kbd> or click the **×** to clear the selection.

Every selection is also written to the agent cursor at `node_modules/.open-pages/current.json`, so you can skip the comment entirely and just tell your agent "make this bigger". See [For agents](/for-agents) for how that file works.

## Leaving a comment

The selection panel has a note field. Write what you want changed, in plain language:

- "make this bold"
- "change to 'Start your free trial'"
- "this section is too cramped on mobile, add breathing room"

Click **Comment**. The dev server writes the comment directly into the page's source as an invisible marker:

```
{/* @page-comment id="c-3f9a1b2c" ts="2026-08-28T14:32:11.123Z" text="eyJub3RlIjoibWFrZSB0aGlzIGJvbGQifQ" */}
```

The marker is a JSX comment inserted as the first child of the element you selected. It never renders, so the page output is unchanged. Because it lives in source, comments survive dev server restarts and show up in git diffs. The `text` attribute is base64url-encoded JSON containing your note.

You can leave several comments across a page, or across multiple pages, before handing off.

## Applying comments

Tell your agent to apply the comments. In Claude Code that is the bundled `apply-comments` skill:

```
/apply-comments
```

The agent finds every `@page-comment` marker, reads the note, edits the enclosing JSX element accordingly, and deletes the marker. Comments it cannot resolve are left in place and reported as skipped rather than guessed at.

As soon as the agent saves the file, the page hot-reloads in your preview. The loop end to end:

<Steps>
  <Step title="Press i">
    Toggle inspect mode in the running preview.
  </Step>
  <Step title="Click and comment">
    Select an element, write a note, click Comment. Repeat for as many elements as you want.
  </Step>
  <Step title="Agent applies">
    Run `/apply-comments`. The agent edits the source and removes the markers.
  </Step>
  <Step title="Preview updates">
    The page reloads. Verify the change, or leave another comment.
  </Step>
</Steps>

<Note>
The source-location attributes that power the inspector are injected only in dev. [`open-pages export`](/export) and `open-pages build` output clean markup without them.
</Note>
