title: "Quickstart"
description: "Scaffold a workspace, author a page with your agent, review it in the live preview, and export it."
icon: "rocket"
---

<Steps>
  <Step title="Scaffold a workspace">
    Run the init command. It copies the workspace template, installs dependencies, and makes an initial git commit.

    <CodeGroup>
    ```bash npm
    npm create @autono/open-pages@latest my-pages
    ```
    ```bash pnpm
    pnpm dlx @autono/create-open-pages init my-pages --use-pnpm
    ```
    ```bash yarn
    yarn dlx @autono/create-open-pages init my-pages --use-yarn
    ```
    ```bash bun
    bunx @autono/create-open-pages init my-pages --use-bun
    ```
    </CodeGroup>

    Useful flags: `--name <name>` overrides the package name, `--force` scaffolds into a non-empty directory, `--no-install` skips dependency installation, `--no-git` skips git init. Run interactively without a directory argument and the CLI prompts for the target and package manager.

    The workspace includes `AGENTS.md` (linked as `CLAUDE.md`), the full shadcn/ui set under `ui/` with its token theme in `styles/globals.css`, and six bundled agent skills: `create-page`, `page-authoring`, `apply-comments`, `current-page`, `create-theme`, and `shadcn`.
  </Step>

  <Step title="Create a page with your agent">
    Open the workspace in your coding agent (Claude Code, Cursor, Codex) and run `/create-page` with a prompt:

    ```
    /create-page a landing page for Meridian, an analytics tool for founders, with pricing
    ```

    The skill asks a few scoping questions (page type and audience, visual direction, sections, interactivity), then writes `pages/<id>/index.tsx`: one React component composed from `@/ui/*` and styled with Tailwind via `className`.
  </Step>

  <Step title="Start the live preview">
    ```bash
    cd my-pages
    npm run dev
    ```

    Open `http://localhost:5173`. Each page lives at `http://localhost:5173/p/<id>`. The viewer runs the real page in a browser frame and hot-reloads on every edit. Use the toolbar to switch between desktop, tablet (820px), and mobile (390px) widths, or hit **Open** to see the page by itself in a new tab.
  </Step>

  <Step title="Inspect, comment, apply">
    In the preview, press `i` (or hit **Inspect**) and click any element. The inspector maps your click to the exact source line and saves each comment into the page as a `@page-comment` marker.

    Back in your agent, ask it to apply them:

    ```
    apply the comments on the landing page
    ```

    The `apply-comments` skill reads the markers, makes the edits, and removes the markers. The dev server also tracks which page and element you last selected in `node_modules/.open-pages/current.json`, so "make this bigger" resolves without naming anything.
  </Step>

  <Step title="Export">
    Build static folders under `export/`:

    ```bash
    # every page → export/<id>/
    npm run export

    # one page
    npm run export -- meridian-launch
    ```

    Each folder holds an `index.html` plus hashed assets with relative URLs. Drop it on any static host. `--out-dir <dir>` changes the output directory.
  </Step>
</Steps>

<Note>
  The agent never needs to touch `package.json`, `open-pages.config.ts`, or `components.json`. Pages are self-contained under `pages/<id>/`, with per-page assets in `pages/<id>/assets/`; the shared `ui/`, `lib/`, and `hooks/` are read, not edited, per page.
</Note>
