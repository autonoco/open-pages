open-pages is a web page framework where an AI coding agent does the authoring. Every page is a React component: HTML JSX styled with Tailwind through `className`, with hooks, state, event handlers, and browser APIs available. A page folder can hold a plain `index.html` instead when that fits better.

The preview is the page. The dev server runs each page as a real document in a browser frame, so what you see at `localhost:5173` is what `open-pages export` writes to disk. Same Vite pipeline, same React, same CSS.

## The loop

1. **The agent writes.** You prompt your coding agent (Claude Code, Cursor, Codex) and it authors `pages/<id>/index.tsx` using the bundled `create-page` skill.
2. **You watch the live page.** `npm run dev` serves the workspace at `localhost:5173`. Every save hot-reloads the page; the toolbar switches between desktop, tablet, and mobile widths.
3. **You inspect and comment.** Press `i` to enter Inspect mode. Clicking any element maps to its exact source line. Comments are saved into the source as `@page-comment` markers.
4. **The agent applies.** Ask the agent to run `apply-comments`. It reads the markers, makes the edits, and deletes the markers. The dev server also writes `node_modules/.open-pages/current.json`, a cursor the agent reads so "this page" and "this element" resolve without you naming them.
5. **You export.** `open-pages export` builds each page into a static folder with hashed assets and relative URLs. Deploy it to Netlify, Vercel, Cloudflare Pages, GitHub Pages, S3, or any static host.

## What a page looks like

A page is one folder under `pages/` with a kebab-case id. Its `index.tsx` default-exports one component and exports `meta`:

```tsx pages/getting-started/index.tsx
import type { PageMeta } from '@autono/open-pages';
import { useState } from 'react';

export const meta: PageMeta = {
  title: 'Welcome to open-pages',
  description: 'The web page framework built for agents.',
  createdAt: '2026-08-28T00:00:00.000Z',
};

export default function GettingStarted() {
  const [count, setCount] = useState(0);
  return (
    <main className="mx-auto max-w-3xl px-6 py-24">
      <h1 className="text-5xl font-bold tracking-tight">The web page framework built for agents</h1>
      <p className="mt-6 text-lg text-slate-600">
        This page is a React component. Your coding agent writes it, the workspace previews it
        live, and the export is plain HTML, CSS, and JS.
      </p>
      <button
        type="button"
        onClick={() => setCount((c) => c + 1)}
        className="mt-8 rounded-full bg-black px-5 py-2 text-white"
      >
        Clicked {count} times
      </button>
    </main>
  );
}
```

Tailwind v4 is configured for you and scans `pages/` and `themes/`. Import `./styles.css` for custom CSS, `./assets/hero.png` for images, and `@assets/...` for files shared across pages.

## Built for agents

A scaffolded workspace ships five agent skills alongside an `AGENTS.md` guide, so the agent knows the file contract before it writes a line:

- `create-page` walks the agent through scoping, structure, and hand-off for a new page.
- `page-authoring` is the technical reference: file contract, styling, layout and responsiveness, interactivity, assets and fonts.
- `apply-comments` turns inspector comments into edits.
- `current-page` resolves "this page" and "this element" from the dev server's cursor file.
- `create-theme` extracts reusable themes as markdown under `themes/`.
