A page folder can hold an `index.html` instead of `index.tsx`:

```
pages/<id>/
  index.html
  style.css      # optional, referenced from index.html
  main.js        # optional, referenced from index.html
```

The workspace treats it like any other page: it appears on the home page with a live thumbnail, previews at `/p/<id>`, gets the viewport toggles, and exports with `open-pages export`. The title on the card comes from the `<title>` tag.

## When to use one

- Hand-written HTML you already have and just want to preview and ship.
- A page that is all markup and CSS with a few lines of vanilla JS.
- Output from another tool that you want to keep verbatim.

For anything with real state or many repeated sections, a React page is easier to iterate with an agent, and it is the only kind the [inspector](/inspector) can map back to source.

## How it is served

In dev, the file is served through Vite's HTML pipeline, so `<script type="module">` and relative `href`/`src` references to sibling files work, and edits reload the frame. Relative URLs are rewritten to point at the page folder.

```html pages/plain-html/index.html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Plain HTML page</title>
    <link rel="stylesheet" href="./style.css" />
  </head>
  <body>
    <main>
      <h1>Plain HTML works too</h1>
      <button id="count" type="button">Clicked 0 times</button>
    </main>
    <script type="module" src="./main.js"></script>
  </body>
</html>
```

`open-pages export` runs a Vite build with the page folder as root, so scripts and styles are bundled and hashed exactly like a React page's. `open-pages build` places the built page under `__page/<id>/` inside the workspace site.

## Limits

- No Tailwind. The generated Tailwind stylesheet is only injected into React pages. Write CSS, or link Tailwind's CDN build yourself.
- No inspect mode or comments. Source-location tags are injected by the React transform.
- No `meta` export. `<title>` is read from the HTML; there is no `createdAt`, so HTML pages sort last by creation date.
- If a folder has both `index.tsx` and `index.html`, the React entry wins and the HTML is just a file in the folder.
